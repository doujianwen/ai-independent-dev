# Lesson 2.1: AI辅助开发实战（修订版）

## 学习目标
1. 掌握AI辅助开发的最佳实践和陷阱识别
2. 学会审查和优化AI生成的代码
3. 实战：完成一个可部署的小型项目

## 1. AI代码生成工作流

### 标准流程
需求分析 → 架构设计 → AI生成 → 代码审查 → 测试 → 部署

### 关键原则
- 你始终是架构师 — AI只是执行者
- 小步快跑 — 每次让AI生成小块代码
- 持续审查 — 不要相信AI生成的代码直接可用

## 2. AI代码审查清单

### 安全检查
- [ ] 有无硬编码密钥？
- [ ] 输入是否验证？
- [ ] SQL注入风险？
- [ ] XSS漏洞？
- [ ] 依赖包是否安全？

### 代码质量
- [ ] 变量命名是否清晰？
- [ ] 函数是否单一职责？
- [ ] 有无重复代码？
- [ ] 错误处理是否完善？
- [ ] 日志是否充分？

### 性能考量
- [ ] 有无N+1查询？
- [ ] 循环内有无数据库调用？
- [ ] 内存使用是否合理？
- [ ] 有无不必要的全量加载？

## 3. 实战项目：AI博客系统

### Step 1: 架构设计
技术栈：
- 前端：Next.js 14
- 后端：Node.js + Express
- 数据库：PostgreSQL
- AI：OpenAI API
- 部署：Vercel

### Step 2: AI生成代码（带审查）

Prompt模板：
请创建一个Next.js博客文章列表组件，要求：
1. 使用TypeScript
2. 包含错误处理
3. 添加loading状态
4. 支持分页
5. 添加JSDoc注释

请分步生成，每步等我确认后再继续。

### Step 3: 测试生成

Prompt：
为以下博客列表组件生成单元测试：
1. 测试正常渲染
2. 测试加载状态
3. 测试错误处理
4. 测试分页功能

使用Jest + React Testing Library。

## 4. 常见AI代码陷阱

### 陷阱1：过度自信
AI生成的代码往往缺少错误处理和边界情况检查。

### 陷阱2：安全疏忽
AI不会主动考虑安全问题，需要人工审查。

## 5. 练习作业

1. 用AI生成一个待办事项API
2. 使用审查清单检查代码
3. 修复发现的安全问题
4. 添加单元测试
5. 部署到Vercel

## 关键要点
1. AI是助手，不是替代 — 你必须理解生成的代码
2. 审查是必须的 — 不要跳过代码审查
3. 测试是底线 — 没有测试的代码不可信
4. 安全是第一位 — 永远不要信任AI的安全意识
