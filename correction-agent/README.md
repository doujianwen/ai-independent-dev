# AI 独立开发实战课 — 纠错智能体系统

## 概述

本模块为"AI 独立开发实战课"项目提供**纯纠错型智能体（Correction Agent）**支持。纠察组只负责挑刺，不负责写方案。它的质疑一旦成立，方案组的成果直接作废，路径被标记「堵死」。

## 核心设计原则

| 原则 | 说明 |
|------|------|
| **角色固化** | 纠察组只分配"找出所有漏洞"的职责，不参与方案构建 |
| **信息隔离** | 纠察组和方案组之间信息不对称，纠察组不知道哪个方案最被看好 |
| **攻击权＞产出** | 纠察组的质疑一旦成立，方案作废；一票否决权 |

## 使用流程

### 1. 启动纠察组

在每个纠错节点（Phase 0 → 1 → 2 → 3）结束时，启动纠察组：

`ash
# 复制日志模板
cp templates/review-log-template.md logs/YYYY-MM-DD-phase{{N}}-cor-01.log

# 用纠察组 Prompt 填充审查对象
# 纠察组成员 ID: COR-01, COR-02, COR-03（至少 2-3 个独立成员）
`

### 2. 纠察组独立审查

每个纠察组成员**独立**填写审查清单，不参考其他组的意见。

### 3. 汇总审查结果

| 结果 | 含义 | 下一步 |
|------|------|--------|
| ✓ 全部通过 | 方案无致命漏洞 | 进入下一阶段 |
| ⚠️ 有条件通过 | 有漏洞但可修复 | 满足前提后进入下一阶段 |
| ✗ 任一"堵死" | 存在致命漏洞 | 方案作废，重新规划 |

### 4. 记录归档

将审查日志存入 logs/ 目录，格式：YYYY-MM-DD-phase{{N}}-cor-XX.log

## 纠察组数量建议

| 阶段 | 纠察组成员数 | 理由 |
|------|-------------|------|
| Phase 0 | 2 人 | 需求验证最关键，需交叉验证 |
| Phase 1 | 2 人 | MVP 产品形态审查 |
| Phase 2 | 3 人 | 营销转化涉及多维度，需要更多视角 |
| Phase 3 | 2 人 | 规模化决策，关注增长可持续性 |

## 人工兜底机制（HITL）

纠察组的结论作为**参考**，最终决策权在人类。当出现以下情况时，触发人工介入：

1. 纠察组之间结论不一致（一个通过、一个堵死）
2. 纠察组标记"堵死"但人类认为可以冒险尝试
3. 纠察组提出的漏洞无法量化评估
